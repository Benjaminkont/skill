# 课程原文择优搬运

把“搬运”理解为内容标准化：来源文件保持原样，从同一内容的多个版本中选出最佳正文，确认后写入课程的 `原文/`。同时检查最终原文中是否存在会改善对应正式笔记的课堂问答。默认一次处理一门课程。

## 两阶段工作流

必须分成两个阶段：

1. **只读预览**：调查候选、比较质量、识别有教学价值的问答，展示整门课程的原文与笔记处理计划，不修改任何文件。
2. **确认后执行**：用户确认整门课程的预览后，才生成、归档或替换原文 Markdown，维护索引与导航，并只向预览中列出的已有正式笔记补入问答。

预览确认是这项工作流的一部分。用户在同一会话中已经确认过具体预览时，不要重复询问。

## 发现与归组

1. 读取来源、目标仓库及课程目录适用的 `AGENTS.md`。
2. 在用户指定目录查找候选；若该目录没有相关内容，可检查同一工作区中明确的转录输出目录，但要在预览中说明实际采用的路径。
3. 支持 Markdown、TXT、JSON、SRT、VTT，以及能用当前工具可靠提取文字的其他文档。音频和视频只作为来源标识，不主动启动语音识别。
4. 优先按规范视频 URL 或媒体 ID 识别同一内容，再结合课程名、标题和讲次。标题中的 `Lecture N`、`Unit N`、`Lec N` 或“第 N 讲”优先于分 P 编号；缺讲保持缺口，不重新编号。
5. 把目标 `原文/` 中已有 Markdown 也纳入候选。排除 README、归档目录和正式课程笔记；正式笔记只用于判断问答是否已覆盖以及确定补入位置，不作为原文候选。

先运行只读分析器收集结构证据：

```bash
python3 scripts/analyze_candidates.py \
  --source /path/to/outputs \
  --target /path/to/course \
  --course CS61C \
  --format markdown
```

可以重复 `--source`。脚本只输出报告，不写文件；它提供完整度、重复度、乱码、讲次和来源信息，不能替代语义质量判断，也不负责判断某段对话是否值得补入笔记。

## 内容质量判断

只比较目标课程且使用原始授课语言的候选。按以下权重形成判断，并写出理由：

- 完整性 35%：覆盖范围、缺段、异常截断；
- 准确性 35%：技术术语、明显识别错误、人工修订质量；
- 连贯性 15%：重复段、循环文本、错序、乱码；
- 可读性 10%：合理分段、标点和正文噪声；
- 可追溯性 5%：标题、视频链接、时间或结构化元数据。

不要按扩展名、修改时间或“clean”字样直接判定质量。现有目标与新候选质量相同时保留现有版本，避免无意义替换。

没有单一候选同时完整且准确时，可以受控合并：以最高质量版本为骨架，只补充能通过时间戳或前后文明确定位的缺段。不要混合不同措辞、润色原话或静默纠错。正文保持干净，所有实际使用的来源写入 YAML。

## 问答判定与笔记补充

对最终选中的原文及实际使用的补段做语义检查。只有当问题与回答能通过说话人标记、对话衔接或前后文可靠识别时，才把它视为课堂问答。

当问答至少满足以下一项时，判定它值得补入笔记：

- 推动课程从初版方案转向下一步改进；
- 暴露常见误解，并给出了有用的纠正；
- 澄清语法、边界条件、失败场景、设计权衡或可移植性；
- 提供了正文中不易恢复的推理过程或反例。

省略只重复刚讲内容、纯课堂管理、礼貌性互动或与本讲学习目标无关的问答。

对每组有价值的问答：

1. 按讲次与主题定位对应的已有正式笔记，并检查其是否已经覆盖问题和回答的实质。
2. 已覆盖时标记“已包含”，不重复插入；有对应笔记但未覆盖时，在预览中列出笔记路径、问答主题和建议插入位置。
3. 没有对应正式笔记时标记“无笔记，不自动创建”。本 skill 不因为发现问答就从零生成整篇课程笔记。
4. 用户确认预览后，把问答放到正式笔记中它所澄清的知识点旁，优先使用 Obsidian callout：

```markdown
> [!question] 课堂问答：简洁的问题
> **学生：** 去掉口语重复后的问题。
>
> **教师：** 保留技术含义和推理的回答。
```

可压缩寒暄、口头禅和重复，但不得虚构对话或把教师的后续总结冒充为学生原话。如果课堂回答含有可验证的技术性简化或错误，保留其为“课堂回答”，并且只在完成验证后追加明确标注的“笔记校正”；不要静默改写课堂立场。

原文 Markdown 仍必须保持原始授课语言、文字与顺序；上述改写只发生在正式笔记中，不得反向润色原文。

## 预览格式

在执行前展示一张覆盖整门课程的表，至少包含：

| 讲次 | 候选 | 最佳骨架 | 补段来源 | 动作 | 问答处理 | 置信度与理由 |
| --- | --- | --- | --- | --- | --- | --- |

原文动作只能是“创建”“保留”“归档后替换”或“跳过”。“问答处理”至少说明“无有价值问答”“笔记已包含”“拟补入：笔记路径与主题”或“无笔记，不自动创建”。另列出缺讲、重复编号、分 P 与讲次不一致、无法解析和低置信度项。获得一次课程级确认后再执行。

## Markdown 输出

沿用课程既有命名；没有约定时，Lecture 使用 `Lec 01.md`，Unit 使用 `Unit 01.md`。无讲次内容使用稳定、可排序的规范标题。

```markdown
---
type: transcript
status: imported
source: "规范视频 URL；未知时使用最可追溯的来源"
migrated_from:
  - "/path/to/backbone"
  - "/path/to/supplement-if-used"
---

# Lecture 1 — Title

原始授课语言的纯正文
```

正文不带时间戳，不翻译、不润色。可以把字幕提示或结构化分段转成 Markdown 段落，但必须保留文字与顺序。

## 确认后执行

1. 在临时目录准备全部目标文件和变更清单，确认文件名唯一、来源仍存在。
2. 替换现有 Markdown 前，将旧文件完整保存到 `原文/归档/<时间戳>/`。所有旧版本都归档，不以 Git 是否跟踪为条件。
3. 原始候选文件全部保留，不删除、不移动，也不改写转录服务的路径索引。
4. 生成或更新 `原文/README.md`，记录课程版本、讲次覆盖、缺讲、编号规则、每讲最终选择和视频链接。
5. 在课程导航中添加或更新 README 入口，避免重复条目。重命名旧原文时先搜索反向引用并同步修复。
6. 按预览中的问答计划更新已有正式笔记；不新建整篇笔记，不对已覆盖的问答重复插入。
7. 只改动预览中列出的课程原文、归档、README、必要引用、课程导航和问答目标笔记；保留其他未提交更改。

## 验证

- 目标文件数、讲次和预览一致，缺讲均有说明；
- 每份正文能追溯到 `migrated_from`，受控补段只来自列出的来源；
- 所有来源文件的哈希在执行前后不变；
- 被替换的旧 Markdown 均存在于归档；
- README、正式笔记与课程导航的相对链接有效；
- 每个新增课堂问答都能追溯到最终原文或 YAML 列出的补段来源，且放在笔记的对应知识点旁；
- 正式笔记中没有重复问答，没有把推测内容写成学生或教师原意；
- YAML、标题、代码围栏和 Markdown 层级有效；
- 对每个涉及的仓库运行定向 `git diff --check`，检查定向 diff 和 `git status --short`，尤其核对未跟踪文件。

最终报告来源目录、目标目录、候选与最终讲次数、创建/保留/替换数量、归档位置、缺讲、合并项、识别的有价值问答数、更新的笔记及验证结果。
