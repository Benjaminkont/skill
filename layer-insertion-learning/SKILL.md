# 层插学习法

“层插”指在层与层之间抽插。本版是用户独立构想、共同整理的试行方法；不要宣称全球首创或学习效果已经验证。

从具体目标出发，展开对理解它有用的周围知识，再沿疑问上下换层。目标是让学习者能解释、区分或应用该事物；“是什么”与“属于什么”在过程中一起变清楚，不设为两道独立关卡。

## 启动与节奏

- 从已有上下文判断目标和已有认识，给出可理解的直接说明，立即开始。只有缺失信息会实质改变讲解时才先询问，不用背景问卷挡住学习。
- 互动学习采用短而完整的局部循环，给学习者追问、纠正和选择方向的机会。要求一次性介绍时，可在一篇讲解里完成必要的几个循环。尊重用户要求的长度、领域和深度。
- 学习者看到的是连贯的解释。不要每换一步就宣布“现在点亮 A”“接着上抽”等流程标签；明确要看方法演示时才展示这些标签。
- 过渡不必每次都写成问句，但要让下一片知识的必要性可感知。

## 按疑问展开

以“确定目标 → 找理解缺口 → 铺垫转移 → 选择方向并展开 → 返回并更新认识 → 检查 → 停止或继续”为决策循环，不作为必须逐项输出的模板。

可用的动作：

| 动作 | 选择依据与解释任务 |
|---|---|
| 同层展开 | 选能照清目标角色、共同点、差异或分工的邻居。交代为何将它们放在一起。 |
| 跨系统弱对照 | 从熟悉现象引出“原来那个系统也有类似部分”，借 x 打开其所在空间 X，让它帮助理解当前目标。说明哪些关系可比、哪里不能照搬。 |
| 向上抽 | 当缺口涉及谁使用它、怎样与它交互、它参与什么整体时，进入相关接口或上层部分。 |
| 向下插 | 当“负责某事”仍只是任务命名时，进入组成或实现，沿具体过程讲清它如何做到。不要只提出“看内部”，随后跳过实际解释。 |
| 递归 | 新部件确实造成理解障碍时，把它作为子目标，以同样方式展开，完成后接回出发问题。 |

“层”由当前理解需要选择，不局限于文件夹、项目或固定分类树，也不等于 OSI 等领域里预先定义的层。不要预设维度全集；具体关系需要准确说明，类型、组成、使用关系与类比不要混写。

不要求每次走完所有动作。横向对照不能替代内部机制；向下插也不意味着必须展开每一个零件。

## 铺垫、回收与注意力

1. 从当前认识里指出尚未解释的问题，或从熟悉现象引出相关邻居。避免“换到另一个系统看看”这样的无动机转场。
2. 引入少量有解释价值的知识；优先选择学习者熟悉或更容易理解的参照。参照本身陌生时，简要说明其相关部分，避免为了解释一个陌生词引入一串新陌生词。
3. 用新知识回答出发时的问题，重新解释本轮目标，让新增或修正的认识可见。维护当前目标、出发问题和返回位置即可，无需把完整路径表展示给学习者。
4. “新部分亮起，旧部分暗下”表示注意力移开：旧知识可在需要时返回。讲解中停止反复复述旧片段；制作可视化时突出当前节点或当前层，让旧高亮和旧连线暗下来。整层进入视野不代表掌握整层。

## 理解检查与停止

- 按本轮目标，选一次有意义的独立解释、易混对象判断、工作过程说明或新例子应用。可以结合学习者自然提出的解释，不强制每轮考试，也不一次堆叠全部题型。
- 一次性讲解可附一个简短自检问题或情境，并让人能先尝试再核对依据。未得到学习者作答时，只能说完成了讲解，不能声称对方已经理解。
- 当前疑问已解决就收束；答错或仍有缺口，围绕具体错误调整参照或方向，不机械重播全流程。用户要求结束或缩短时遵从。
- 停止在目标所需的深度，不把邻居全部教完，不用递归把局部问题扩成整门课程。

技术事实与类比边界要站得住：需要核实时使用相应来源；简化示意应标明范围，不让流畅叙述掩盖缺失机制或未经核实的对应关系。
