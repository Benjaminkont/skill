# 层插学习法

从学习者已经遇到的具体对象出发，借周围知识照清它的含义、作用与边界。先准备知识网络，为后续兴趣保留探索入口；再生成可以独立阅读的完整讲义，根据反馈继续探索。

## 确定本轮对象

结合问题与上下文，明确要理解的是概念、实例还是机制，以及当前疑惑。能判断就直接开始；只有歧义会改变讲解路线时才澄清。宽泛目标先收敛到具体起点。

例如，理解“进程”时，浏览器进程是实例；理解“这个浏览器进程”时，其他运行中的进程才可能成为比较对象。引入新对象时也保持这个区分。

## 先准备可复用的知识网络

共享知识库：`/Users/quzhong/GitHub/skill/skill/knowledge-networks/`，入口为其中的 `INDEX.md`。它独立于 skill 安装目录和本轮工作目录。用户明确指定其他知识库时使用指定路径；隔离验收也使用临时副本。

在生成讲义前，完成本轮网络的查找、必要增补或创建并保存：

1. **查索引选候选。** 根据学习对象和本次问题，结合网络名称、别名、典型术语与覆盖范围查找。系统或稳定主题是复用单位，不能只凭关键词重合判定命中。
2. **读正文确认范围。** 阅读候选网络的相关部分。多份网络有关时，选择最贴合当前问题的一份为主网络，并链接其他网络；不因存在重叠就重复建网。
3. **补充或创建。** 已有网络范围适用但缺节点时增补；没有适用网络时，新建以系统或稳定主题命名的 `*-structure.md`，并登记索引。首次准备系统主要领域和关系，细化当前对象附近的节点，不追求穷尽整个系统，也不规定层数和节点数。
4. **保持索引与正文一致。** 索引记录名称、别名与典型术语、覆盖范围、文件链接、相关网络；正文保存知识骨架和必要关系，使用能打开的链接连接相关网络。本轮起点标记与讲解路线放在讲义中，不固化进共享网络。

网络是可增补的组织视角，不是唯一分类标准。已有节点不等于本次必须讲解的内容。网络中的示例路径供选择，不是每次的执行清单。

新增网络、补节点和修正明确错误可以直接进行，完成后简短告知。改名、合并、删除或整体重分类先讨论。保留已有有效内容；不确定的关系说明待核对，不把猜测当成事实存入网络。

如果共享库无法读取或写入，说明具体阻塞，不把读取失败当成没有命中，也不悄悄在安装目录或工作目录建立另一份共享库。

## 四个方向与路径选择

默认按“同层 → 向上 → 跨系统 → 向下”考虑探索方向，讲义的呈现顺序按内容安排。四个方向都要评估并呈现；没有合适内容的方向简短说明原因，不为覆盖方向凑邻居或编造类比。

- **同层对照：** 在当前问题下，比较共同角色、共同问题或选择范围内的对象，说明比较依据及关键差异。可以跨越网络的固定分类，但不混淆概念与实例，也不把无关对象强放在一起。例如，merge、rebase、cherry-pick 在“整合代码的方式”这个视角下可以比较。
- **向上抽：** 看它属于什么整体、谁使用或管理它、解决什么更大的问题；必要时联系支撑它的理论，解释它的作用与设计理由。
- **跨系统对照：** 借学习者熟悉的系统照清一个有帮助的特征，交代借用范围和不能照搬的关键差异。相似点不设配额；找不到可靠对应时说明不适用，不硬套。
- **向下插：** 看组成、实现机制或具体执行过程，解释它如何工作以及限制从何而来。机制与过程不必都表示成树中的组成节点。

知识网络提供后续入口，讲义围绕本轮对象展开。引入邻居时说明其作用及与目标的关系；只有必要前置知识或用户希望深入时，才把它作为新目标继续展开。根据理解目标决定深度，并保留返回原问题的路径。

## 讲成一份连贯的讲义

先直接解释对象是什么，补足理解所需的背景，串起关键关系与机制。读者应能独立理解当前对象，不把关键缺口留待追问补完。

标题围绕内容组织，不按四个方法名机械排章节。切换视角时，用贴合当前认识的反问引出联系、缺口或必要性，紧接着解释，不等用户先答题；同一视角内无需反复设问。表格、图示、例子按内容需要选择。

新部分成为焦点时，旧部分退到背景；展开后回到出发时的问题，说明新增认识帮助理解了什么。不要求把网络中的整层内容讲完，也不规定章节、段落、邻居、误区或内部组成的数量。

通过后续回应观察理解。有助于暴露关键误解时，可在讲义末尾附可选场景题及答案；不要求先复述或答题才能继续。发现误解后，回到相应关系或机制换角度解释。

## 交付与自检

讲义默认写入当前工作目录的 `layer-insertion-docs/[主题].md`，用户指定位置优先。根据本轮意图续写同一讲义或新建文档，避免覆盖无关的已有笔记。讲义引用实际使用的网络，使用相对讲义位置有效的路径或绝对路径，不能只写裸文件名。

交付前核对：网络已准备且命中范围正确；四方向均有内容或不适用说明；关系与类比没有误导；关键疑惑已解释；文件与引用可打开。对话给出讲义概述和链接，简短说明网络新增或修订情况。

当前仓库的案例位于本文件目录的 `../examples/`，演示位于 `../demo/`，按需阅读。旧案例保留其原有讲法，不能把旧案例中的章节和数量要求反过来当成当前规则。

v0.5 场景验收通过后，至少完成 5 次真实使用再讨论方法调整。期间只修明确错误，正常积累网络；将真实使用的主题、命中结果、实际问题记入 [TODO.md](TODO.md)，重复出现的方法问题再集中讨论。隔离验收不计入真实试用。
