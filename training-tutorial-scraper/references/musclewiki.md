# MuscleWiki 获取经验

适用于已确认的 MuscleWiki 动作页。页面、媒体域名或工具 API 可能变化，执行前以当前 DOM 和工具文档为准。

## 页面与媒体

- 动作页示例：`https://musclewiki.com/zh-cn/exercise/dumbbell-curl`。
- 中文页面可能仍显示英文，必要时读同一动作的英文原页；保留实际核对的来源。
- 2026-11 的实际页面中，循环演示是两个 `<video>`，步骤与动作属性位于 `<dl>`。YouTube iframe 可能是整组肌群的长教程，与两个短演示分别处理。
- `front`、`side` 可帮助标记角度，但不要根据 slug 推算媒体地址。实际文件可能包含大小写差异、额外后缀，两个元素的顺序也可能不同。

浏览器工具允许只读 DOM 查询时，可依据当前页面执行类似逻辑：

```javascript
({
  videos: Array.from(document.querySelectorAll('video')).map(v => ({
    url: v.currentSrc || v.src
  })),
  text: Array.from(document.querySelectorAll('dl')).map(x => x.innerText)
})
```

这段用于读取渲染页面，不访问隐藏状态、认证信息或无关接口。阅读当前工具文档后，再用其受支持的执行方式调用。

## 浏览器下载路径

在支持的 CUA 浏览器环境中，曾成功使用：

- `pageAssets` 能力的 `list()` 获取已观察素材，再用 `bundle()` 按具体视频 ID 导出。
- 当前页面视频元素的 `downloadMedia()` 直接下载媒体；这对素材清单暂未刷新时也有用。

切换页面后先观察新页面并确认视频已出现。素材清单为空时检查页面加载状态，不把空清单当成动作没有演示。导出返回的本地路径可能位于临时目录或默认下载目录，应将所需素材复制到知识库并比对哈希。

一次实际任务中，直接 Python HTTP 请求返回 403，正常浏览器页面却可公开访问并下载演示。这只是工具访问差异的实例，不是绕过网站访问控制的许可。

## 文字核对

- 先提取编号步骤，再按需读更长的准备与动作说明。
- 中文“反手弯举”与握法术语“正握”可能并存，说明掌心朝向比只复制握法词更清楚。
- 曾发现腕伸展页面简述写“反握”，同页握法写“正握”；当时结合视频和详细说明归纳为掌心朝下。以后遇到冲突仍应重新核对，不能把这次修正套到所有动作。
- 动作分类可能包含次要参与肌群的复合动作；整理手臂动作时核对目标关节与用户范围，不机械收录分类页全部内容。
