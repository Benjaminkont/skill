# 训练教学爬取

## 调用边界

**仅显式调用。** 用户必须明确要求使用“训练教学爬取”或 `$training-tutorial-scraper`；仅出现训练网站、动作名称、下载、GIF 或笔记等词，不启用本技能。创建、介绍或修改技能本身，不等于要求执行爬取。

`agents/openai.yaml` 中保持 `policy.allow_implicit_invocation: false`，除非用户明确要求改变。

## 确定范围与归置

- 从当前对话取得目标网站、已选动作与保存目录。用户说“这些动作”时沿用已确认清单；不把一次选定的 13 个动作或“哑铃优先”固化为以后任务的限制。
- 若只要求先找候选，给出可核验链接与器械条件；明确要求保存时，再下载已选条目。
- 读取目标仓库规则及相邻笔记，搜索重复动作。已有内容优先补全；保留用户修改，覆盖同名笔记或附件前比较内容。
- 一动作一篇，默认命名为 `肌群 ｜ 动作名称.md`，例如 `三头肌 ｜ 单臂哑铃过顶臂屈伸.md`。保留全角 `｜` 和两侧空格；肌群是检索分组，不表示动作只涉及该肌群。
- 新素材按目标主题的布局保存，默认 `assets/<动作名称>/`。重命名先查反向引用，更新索引及素材清单；不为了匹配笔记文件名而强制移动可用附件。

## 获取网页与演示

1. 优先采用环境中可用的网页读取、浏览器或站点工具。先查工具文档；CLI 不可用时换可用工具，不假定已安装，也不擅自修改全局环境。
2. 从实际打开的动作页提取标题、器械、握法、步骤与演示媒体。看起来像动图的播放器可能实际使用 MP4；读取渲染 DOM 的媒体元素及 `src/currentSrc`，不猜拼媒体 URL，不下载嵌入的无关长视频。
3. 直接 HTTP 请求失败时，可用正常浏览器检查公开页面是否可访问。登录、验证码、付费墙或明确禁止访问的路径按实际权限处理；不伪造身份、绕过限制或反复撞失败地址。无法获取的项目保留来源与失败说明，继续其他可完成项目。
4. 只下载本批笔记需要的动作演示；页面提供正面、侧面等互补角度时保留角度信息。无需重复抓取不同性别、语言或器械变体，除非用户要求。
5. 为每个素材记录动作页、媒体原址、本地相对路径、获取日期。保留原视频，并记录 SHA-256、时长与尺寸，便于后续核验与重命名同步。去掉跟踪参数，不记录凭据或访问令牌。

遇到 MuscleWiki 时按需读取 [references/musclewiki.md](references/musclewiki.md)；其中是经过实践的获取方式，不是永远有效的 URL 模板。

## 制作本地 GIF

- 已有可用 GIF 时直接保留；原件是 MP4 时使用 `ffmpeg` 转换，保持完整片段、原始速度和水印。用户授权剪辑时再裁剪。
- 默认宽 640 像素、15 fps、最多 160 色、循环播放。源视频更小时不放大；可按清晰度与体积调整，不把参数误写成动作要求。
- 转换助手：`scripts/video_to_gif.py`。它只处理本地视频，拒绝覆盖已有文件，调用 `ffmpeg/ffprobe` 并核验生成结果；依赖缺失则说明，不擅自安装系统软件。

适用 macOS/Linux，任意工作目录；需 Python 3、PATH 中的 `ffmpeg` 与 `ffprobe`。传入已下载视频和目标 GIF 的实际路径：

```bash
python3 /path/to/training-tutorial-scraper/scripts/video_to_gif.py \
  '/path/to/动作/正面.mp4' '/path/to/动作/正面.gif'
```

## 整理中文教学笔记

最小 YAML 为 `type`、`status`、`source`；`source` 指向实际核对的动作页。正文围绕以下内容组织，按动作复杂度调整篇幅：

- **动作概览**：中英文名、器械、握法与肌群分组；有解剖综述时链接对应章节。
- **动作演示**：各角度 GIF 用相对 Markdown 图片链接嵌入，并提供原始 MP4 链接；说明 GIF 来自视频转换。
- **动作步骤**：根据来源归纳成中文、可执行的起始—运动—回位顺序，不把网页全文或完整翻译当成原创。补齐衔接动作时标明属于整理。
- **动作要点**：只写能从来源、演示或可靠解剖资料支持的提示。源站翻译冲突时交叉核对并保留说明；不无声照抄误译，不把肌群标签夸大成“孤立某个头”。
- **来源与素材**：原页及媒体链接、获取日期和作者/站点署名；不虚构开放许可。
- 文末 **`## 文章讲解`**：明确标为补充讲解，用关节动作、相近动作对照或可观察的错误降低理解门槛，不只重复步骤。不擅自添加个体训练处方、伤病诊断或未经核验的效果承诺。

新增普通链接、图片采用目标库的相对 Markdown 路径；文件名空格按相邻笔记约定编码，表格中注意全角分隔符与路径语法。批量保存时增加或更新动作索引和对应主题导航。

## 验证与交付

- 对照选定动作清单确认每动作一篇、媒体角度匹配；取帧检查演示确实对应动作，保留源站角度命名。
- 检查 GIF 多帧、循环设置、尺寸和时长；完整解码 GIF 与 MP4；比对原视频哈希，不能把文件存在当成下载成功。
- 检查 YAML、连续标题层级、代码围栏、内部链接、图片与视频相对路径。同步更新素材清单；不能只修 Markdown 而留下旧附件路径。
- 对涉及文件运行 `git diff --check` 并审阅定向 diff。未跟踪笔记用 `git diff --no-index --check /dev/null <文件>` 补查，不暂存无关改动。
- 最后给出索引或目录链接、实际完成数量与未完成项；只声称实际做过的解码或渲染验证，不自动提交或发布。
