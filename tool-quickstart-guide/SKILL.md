# 工具快速教程

让读者从一个真实任务出发，尽快达到“能独立操作、解释关键行为、判断适用边界”的程度。“快速”指缩短到达这个目标的路径；篇幅由必要的学习步骤决定。

## 确定读者起点与学习终点

结合用户的实际命令、困惑、目标产物、平台，以及已有笔记建立最小学习者画像。区分已知信息与推测：不熟悉当前工具的读者，可能已经熟悉相关语言、系统或其他工具。能从上下文推断的条件不必再次询问；只有影响正确性或教学路径且无法推断的信息才需要澄清。

把目标写成可观察能力，例如独立完成任务、解释输入到输出的变化、选择合适选项、定位常见失败所在的层。列出本次的停止边界与必要前置条件；用户只问一项功能时，教程围绕该功能展开。

在作者工作过程中先形成简短的教学纲要：读者起点 → 目标任务 → 必要概念 → 关键观察 → 完成标准。成品优先呈现读者需要的内容，设计与研究过程按需保留。

## 先寻找资料，再判断哪些内容值得借鉴

在起草教程前查找现成教程和当前官方资料。优先检查官方入门、维护者示例，再按教学缺口寻找可信的社区材料；没有合适教程时，依据官方资料自行设计讲解。针对软件版本、参数和已引用页面读取实际内容，搜索摘要只用于发现来源。

资料各有用途：官方文档通常用于核对事实与适用版本；教程用于研究解释顺序、案例与前置知识处理。对候选资料检查：

- 来源与维护状态是否可追溯，版本是否适合当前任务。
- 案例是否完整，起始条件与预期结果是否清楚，关键操作是否存在无法解释的跳步。
- 原理说明、失败场景与适用边界是否有依据。
- 预设知识、任务与目标读者是否相近；有价值的片段能否迁移到本次教程。

对拟借鉴片段，明确“解决了哪种学习障碍、靠什么安排帮助理解、成立需要哪些条件”。保留具体章节或页面来源，筛掉过时操作、无效类比和与当前目标无关的展开。下载量、星标和榜单排名只能辅助发现，不能替代内容判断；既有教程的大纲也需要重新匹配学习目标。

## 围绕困惑组织教学，而非罗列功能

优先以用户遇到的真实命令、界面动作或输出作为贯穿案例。先让读者知道它解决什么问题，再解释要完成它必须认识的对象、组件、状态或数据流，随后实践并回到原场景。篇章数量和具体顺序根据任务调整。

用下面的判断控制解释方式与细节：

- **初学者感受不到问题时：** 展示他们能理解的手工做法、缺失条件或小规模失败，再给出可观察的错误、差异或代价，说明工具为何提供相应机制。讲清成立条件与合理替代方案，避免把一个解决方式写成唯一选择。
- **第一次出现陌生概念时：** 在使用前给出完成当前任务所需的最小定义和例子。较大的前置主题链接已有资料，说明何时必须先学；不要递归展开成另一门课程。
- **容易混淆的概念：** 用对照案例区分它们管理的对象、作用范围、执行时机和结果。需要时使用表格或小图，类比用于辅助，因果解释仍落在机制上。
- **细讲的内容：** 会影响操作成败、后续理解或自主判断的行为与边界，尤其是默认值、状态变化以及多层工具各自负责的动作。
- **可压缩的内容：** 重复操作、旁支功能和非必要实现细节。省略步骤时保留起始条件与关键检查点；任何完成主任务所必需的步骤都应可恢复。
- **章节关系：** 先提供后文依赖的概念，再引用它。章节结束留一个可判断的结果；供独立查阅的部分简要重述环境与状态，避免读者靠猜测补齐隐含条件。

## 让关键区别可以被观察

当实验能解决理解障碍时，设计一个最小、完整的实践，围绕可证伪的预测组织：先说明会观察什么，执行后比较实际结果，再解释差异由哪个机制产生。对照实验尽量只改变一个关键条件。

实践可以是命令、可读的界面操作、样例项目或已有示例。只有确实节省重复劳动或提高复现可靠性时才附脚本；不要为所有工具强制创建模拟器、沙箱或复杂实验工程。

命令与操作应交代平台、Shell 或界面版本、当前目录或初始状态、必要依赖、权限和文件变化。预期输出可以摘录，变化的路径与数值要标明。可执行示例、需要替换的模板和概念示意需要区分，让读者知道什么可以直接运行。

验证采用任务已授权范围内的最小操作。写教程本身不代表用户要求安装外部工具、修改全局配置或执行真实业务动作；这类步骤可先提供说明与验证方式。无法运行时标明所依据的资料和未验证条件，不把推测或模拟结果写成工具实测。

## 分别检验技术、教学与产物

技术检查围绕事实、参数、版本、案例起始条件和观测结果进行。运行可行且必要的最小示例；遇到差异先确定原因，再修改教程。明确哪些经过实测、哪些来自文档、哪些仍待验证，给出失败时先检查的层或状态。

教学检查使用完成标准：读者是否能独立完成主任务，改变一个关键条件后预测结果，解释一个容易混淆的行为，并判断何时停止使用或改选方案。适合时提供少量自测或迁移任务及答案；篇幅、术语数量和命令运行成功都不能单独证明学会了。只有存在学习者实际反馈时，才据此宣称画像或教学效果得到验证。

保存教程时沿用目标位置的组织和格式，先检查已有同主题笔记，按需补充相关入口与链接。交付前检查涉及文件的结构、代码块、相对链接和修改范围。未指定文件产物时按用户要求返回教程，不自行创建额外目录、日志或审计报告。

最终交付应让读者找到教程和必要附件，并简要知道适用范围与验证限制。持续改进依据实际卡点与失败案例作局部调整，避免把一次工具特例固化为所有教程的规则。
